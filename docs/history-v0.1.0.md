# LYRION — Beyond the Stars

ブラウザで動く3D宇宙探索ゲーム。架空の「リリオン星系」を宇宙船で巡り、天体をスキャンして探査データを集め、船を強化して次の天体へ向かう。

- 技術: TypeScript / Three.js (WebGL) / Vite。実行時の依存は `three` のみ。
- セーブは `localStorage`（キー: `lyrion.save.v1`, `lyrion.settings.v1`）。
- アセットは外部ファイルなし。惑星・雲・星空のテクスチャは**起動時にGPUでベイク**して生成する（`src/render/bake.ts`）。

> **検証状況について（重要）**
> 開発環境にはGPUがなく、ブラウザ確認は **Chromium + SwiftShader（ソフトウェアGL）** のみ。
> ゲームロジックと画面表示は実ブラウザで確認済みだが、**実GPUでのフレームレートは未計測**。
> 「60fps / スマホ30fps」の目標は**達成を主張できない**（[検証状況](#検証状況)参照）。


> Codex など他のエージェントへ引き継ぐ場合は、まず **AGENTS.md**（作業手順と守るべき約束）を読むこと。

## 起動・ビルド

```bash
npm install
npm run dev          # 開発サーバ (http://localhost:5173)
npm run typecheck    # tsc --noEmit
npm test             # 単体テスト (vitest, 22件)
npm run build        # 型チェック + 本番ビルド → dist/
npm run preview      # dist/ を配信して確認
npm run test:e2e     # 実ブラウザのE2E: smoke.mjs(基本フロー) + touch.mjs(タッチ操作)（要 playwright、下記）
```

E2Eは `playwright` を devDependency に含めていない（ブラウザ取得が重いため）。
`npm i -D playwright && npx playwright install chromium` の後、`npm run build && npm run test:e2e`。
`PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs` でも指定できる。実行するとスクリーンショットが `docs/screenshots/` に出力される。

URLに `?debug` を付けると `window.__lyrion`（`Game` インスタンス）が公開される。E2Eはこれを使って `tick()` を手動で進める。

### タッチ操作（スマホ/タブレット）

タッチ端末では自動で有効（PCでも最初のタッチで有効化）。左: 仮想スティック（前後/左右）、画面の空き部分をドラッグ: 視点、右: SCAN / TGT / BRAKE / BOOST(長押し) / ▲▼、上部: CAM / II(一時停止)。
Pointer Lock は使わない。実装は `src/ui/TouchControls.ts` と `Input.virtual` / `Input.addLook`。**実機では未検証**（エミュレーションのみ）。

## ゲームの流れ

「移動 → 発見 → 接近 → スキャン → 報酬 → 強化 → 次の探索」。8段階のミッション（約5〜10分）が目的を案内する:
シンドラ → タラッサ → 船の強化 → 小惑星帯 → アウレリオン → その衛星2つ以上 → 星系の果て(ヴェスパー) → 全天体の完全調査。

天体は11個: 恒星 LYRION、岩石惑星 CINDRA、海洋惑星 THALASSA（大気・雲）、衛星 LUMEN、小惑星帯 HALCYON、
リング付きガス惑星 AURELION と衛星 EMBER / GLACIA / MIRA、氷惑星 VESPER、探査機の残骸 WAYFARER-3。
直径・温度・組成は架空だが科学的にもっともらしい値（`src/data/starSystem.ts`）。**ゲーム内スケール（radius, orbit）と設定上の実値（realDiameterKm 等）は別フィールド**。

## ソース構成

```
src/
  core/      Game.ts(統括・ループ・状態遷移) state.ts(GameState) events.ts hud.ts(HUD用スナップショット型)
  data/      starSystem.ts(天体定義) missions.ts upgrades.ts types.ts   ← コンテンツはここを編集
  physics/   flight.ts(慣性・アシスト・Floating Origin) orbits.ts(公転)
  systems/   scan.ts upgrades.ts missions.ts save.ts settings.ts collision.ts   ← three/DOM非依存で単体テスト可
  render/    BodyView.ts(惑星/雲/大気/リング/LOD) SunView.ts Sky.ts AsteroidBelt.ts(Instanced)
             SpaceDust.ts ShipModel.ts ChaseCamera.ts bake.ts(GPUベイク) shaders.ts quality.ts(画質段階+Auto)
  input/     Input.ts
  ui/        Ui.ts(メニュー/パネル) Hud.ts style.css dom.ts
tests/       logic.test.ts(vitest)  e2e/smoke.mjs(Playwright)
```

設計上の要点:
- **Floating Origin**: 船が原点から1500u離れるとワールド原点を移し替える（`maybeRebaseOrigin`）。描画は常に原点相対。
- **天体位置は時刻の純関数**（`orbits.ts`）。N体計算なし。セーブには時刻だけ持てばよい。
- **LOD**: 惑星は距離に応じて球の分割数を切り替え、遠方の衛星は描画距離で非表示。小惑星帯は `InstancedMesh`。星空は `Points`（GPU負荷が小さい）。
- **画質**: `QUALITY_LADDER`(L0〜L5)が解像度スケール・星数・小惑星数・分割数・雲・バンプ・グレアを一括で決める。Low=L1 / Medium=L3 / High=L5 固定、Auto は `AutoQuality` が実測FPSで段階的に下げる（一度下げた段より上へは戻らない）。
- 非表示タブでは描画を止める（`visibilitychange`）。WebGLコンテキスト喪失/復帰、描画例外の連続発生時のエラー画面あり。

## 実装済み機能

- 3D宇宙空間: 星空（色・明るさの異なる星＋星雲）、恒星光源、宇宙塵による速度感

- HUD（速度・エネルギー・船体・目的地距離・ターゲット・スキャン進捗・方位・目標マーカー）、メインメニュー、記録、アップグレード、設定、一時停止、クリア画面
- 画質 Low/Medium/High/Auto、FOV・感度・Y反転・FPS表示
- タッチ操作UI（仮想スティック・ボタン・ドラッグ視点）、小さい画面向けのHUD/メニューの詰め表示

## 今回の検証で見つけて直した不具合

1. **大気が円盤全体を白く塗りつぶしていた**（`render/shaders.ts` の `ATMO_FRAG`）。
   光学的厚みを `uStrength / H` で正規化していたため、真上から見ても濃度が約1.0になっていた。
   `ATMO_THIN = 0.14` を導入し、縁（接線方向の長い経路）だけが光るようにした。
   修正前: タラッサは白青の球・アウレリオンは画面の約21%が白飛び。修正後: 海・大陸・金色の縞模様が見え、縁に薄い大気光が出る。
2. **メインメニューが低い画面で切れていた**（高さ360pxで「設定」に届かない）。スクロール可能にし、低い画面用に詰めた。
3. **HUDが480px幅で重なっていた**。`max-height:480px / max-width:560px` 用のコンパクト表示を追加。

## 既知の不具合・注意点

- タラッサは雲が厚く、近距離では白っぽく見える（雲の被覆率・明るさの調整余地）。
- 惑星のテクスチャは起動時にベイクするため、初回ロードで一時的に重い。実機での所要時間は未計測。
- `debugTeleport()` は最初の `tick()` より前に呼ぶと天体位置が未更新で恒星の中へ飛ぶ（デバッグ専用）。
- ソフトウェアGLでは、High・960×540で描画がタイムアウト/ページ停止した。実GPUでの再現性は不明（要確認）。
- ポインタロックはクリックで有効化する（「クリックして視点操作を有効化」の表示）。

## パフォーマンス上の注意

- 最も重いのは大気（フルスクリーン級のフラグメント）、雲、バンプ、大きな惑星に近づいたときの重なり描画。負荷が出たらまず `QUALITY_LADDER` の `renderScale` / `clouds` / `bump` を見る。
- 新しい惑星/衛星を足すとベイク時間とテクスチャメモリが増える。`bakeWidthFor()` が画質別のテクスチャ幅を決める。
- 毎フレームの割り当てを避けるため、`Vector3` などは再利用している（`_v1` 等）。追加コードでも `new` をループ内に置かない。
- 球ジオメトリは分割数ごとに共有し、不要になったら `pruneSphereGeos` で破棄する。

## Codexが優先して改善すべき項目

1. **実GPUでの計測**（PC/スマホ）。`?debug` + FPS表示で Low/Medium/High/Auto を比較し、`QUALITY_LADDER` と `AutoQuality` の閾値を調整。
2. **タッチ操作の実機確認と調整**（スティック径・視点ゲイン `LOOK_GAIN`・ボタン配置・iOS Safari でのジェスチャ/セーフエリア）。
3. **操作感の調整**（`physics/flight.ts` の推力・減衰・アシスト強度）。実際に遊んで確認すること。
4. 初回ロード（ベイク）の分割・進捗表示、`OffscreenCanvas`/非同期化の検討。
5. タラッサの雲・大気の見た目調整、近距離での惑星表面ディテール。
6. 音。
7. 長時間プレイでのメモリ・GPUリソースの確認（`renderer.info.memory`）。
8. 他ブラウザ（Safari/Firefox）での動作確認。

既存機能を壊さないために: 変更後は必ず `npm run typecheck && npm test && npm run build` を通し、描画・入力に触れたら `npm run test:e2e` も実行する。
天体・ミッション・アップグレードの追加は `src/data/` の編集だけで済むよう作ってあり、`tests/logic.test.ts` が参照整合性と進行可能性（全スキャンで全ミッション完了・報酬で初期強化を購入可能）を検査する。
